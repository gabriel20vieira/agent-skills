# dev-crew Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Criar o plugin `dev-crew` no marketplace `agent-skills`. Uma equipa de subagents
(Opus coordena, Sonnet desenvolve, Haiku verifica) trabalha em worktrees por área e é
monitorizada numa dashboard Artifact com limites por modelo.

**Architecture:** O plugin tem uma skill (`dev-crew`) que conduz a sessão principal, três
agents (`coordinator`, `developer`, `checker`) com o modelo fixo no frontmatter, um script Node
que gere as worktrees e os branches da corrida, e uma página Artifact (`index.html` mais
`logic.js`, com a lógica pura testável) que lê e escreve na `db` do Artifact.

**Tech Stack:** Markdown (skill e agents), Node ≥ 22 ESM sem dependências (`node:test`,
`node:child_process`), git worktrees, HTML/JS de Artifact com as capabilities `db` e `user`
(runtime contract 0.2.85).

**Spec:** `docs/superpowers/specs/2026-10-17-dev-crew-design.md`

## Global Constraints

- Estilo: 4 espaços, aspas duplas, sem ponto e vírgula. Código, comentários, skills e frontmatter
  em inglês.
- Só npm. Os scripts não têm dependências: apenas `node:*`.
- Modelos e effort dos agents: `coordinator` → `opus`/`high`, `developer` → `sonnet`/`medium`,
  `checker` → `haiku`/`low`.
- Limites por defeito: `{ opus: 2, sonnet: 4, haiku: 6 }`.
- "Sem sinal": `updatedAt` com mais de 10 minutos (`600000` ms).
- Voltas: até 3 voltas de check por developer, e até 2 devoluções por task do coordenador.
- Branches `crew/<runId>` e `crew/<runId>/<area>`. Worktrees em `<pai do repo>/<nome do repo>-crew/<runId>-<area>`
  (e `<runId>` para a da corrida).
- O código nunca faz push, PR, merge para o branch do utilizador, nem apaga branches.
- O `web-foundation` e o template ficam intocados. `npm run check` no template não é afetado.

## Decisões do plano (não estão na spec)

- **Agentes por corrida:** em vez de `agents/<agentId>`, os agentes ficam em
  `runs/<runId>/agents/<agentId>`. Assim, o mesmo `<role>-<n>` não colide entre corridas, e
  a página lê só a corrida selecionada.
- **Script de worktrees:** os passos de git da secção 4 da spec ficam num script testado
  (`worktrees.mjs`), em vez de comandos soltos na skill. Isto reduz os erros do modelo.
- **Página em dois ficheiros:** `index.html` (render e `db`) e `logic.js` (funções puras,
  testadas com `node --test`), publicados juntos através de `files`.
- **Merge numa worktree da corrida:** o merge das áreas é feito numa worktree própria do branch
  `crew/<runId>`, para nunca mexer no checkout do utilizador.

## Review Focus

1. Corrida iniciada com alterações por commitar: tem de recusar com uma mensagem clara e não
   criar nada (teste na Task 2).
2. `runId` ou área com espaços, `/`, `..` ou maiúsculas: tem de ser rejeitado antes de chamar o
   git (teste na Task 2).
3. Conflito entre duas áreas no merge: aborta o merge dessa área, reporta-a e o branch da
   corrida fica com as restantes (teste na Task 2).
4. Agente preso em `running` há mais de 10 minutos: não conta para os limites e aparece como
   "sem sinal" (teste na Task 3).
5. Dashboard aberta pela primeira vez, sem `config/limits` nem corridas: mostra os limites por
   defeito e um estado vazio, sem erro (teste na Task 3 e verificação manual na Task 4).

### Task 2: Script de worktrees da corrida

**Files:**
- Create: `plugins/dev-crew/skills/dev-crew/scripts/worktrees.mjs`
- Test: `plugins/dev-crew/skills/dev-crew/scripts/worktrees.test.mjs`

**Interfaces:**
- Produces (exportado e também usado como CLI):
  - `startRun({ repo, runId, areas, install }) -> { base, runBranch, worktrees: [{ area, branch, path }] }`
    - `install` é opcional (uma string de comando que corre em cada worktree).
  - `mergeRun({ repo, runId }) -> { path, merged: string[], conflicts: string[] }`
  - `cleanupRun({ repo, runId }) -> { removed: string[] }`
  - `crewRoot(repo) -> string`, que devolve `<pai>/<nome>-crew`.
  - CLI: `node worktrees.mjs start <runId> <area...> [--install "<cmd>"]`, `merge <runId>` e
    `cleanup <runId>`. Corre no repo do diretório atual e imprime o resultado em JSON.

- [ ] **Step 1: Escrever os testes que falham.** Cada teste cria um repo git temporário com
  `mkdtempSync`, configura `user.name` e `user.email` localmente e faz um commit inicial.
  - `startRun creates run and area branches with worktrees`: com as áreas `api` e `ui`, existem
    os branches `crew/r1`, `crew/r1/api` e `crew/r1/ui`, ambos os `path` existem, e `base`
    é o `HEAD` de partida.
  - `startRun refuses a dirty tree`: com um ficheiro por commitar, lança `/Uncommitted changes/`
    e não cria nenhum branch `crew/*`.
  - `startRun rejects unsafe ids`: com `"R 1"`, `"a/b"`, `".."` ou `"UI"`, lança
    `/Invalid id/`.
  - `startRun refuses an existing run`: chamado duas vezes com `r1`, lança `/already exists/`.
  - `startRun runs install in each worktree`: com
    `install: "node -e \"require('fs').writeFileSync('x','1')\""`, o ficheiro `x` existe em cada worktree.
  - `mergeRun merges every area`: com commits em ficheiros diferentes em cada área, devolve
    `merged: ["api","ui"]`, `conflicts: []`, e os dois ficheiros existem em `path`.
  - `mergeRun reports conflicts and keeps the rest`: com as duas áreas a alterar a mesma
    linha, devolve `merged: ["api"]` e `conflicts: ["ui"]`. O branch da corrida fica limpo
    (sem merge a meio).
  - `cleanupRun removes worktrees and keeps branches`: os caminhos deixam de existir e os
    branches continuam.
- [ ] **Step 2: Correr e ver falhar.**
  Run: `node --test plugins/dev-crew/skills/dev-crew/scripts/worktrees.test.mjs`
  Expected: FAIL (o módulo não existe).
- [ ] **Step 3: Implementar.** Usa `execFileSync("git", [...], { cwd })`, nunca uma shell com
  ids interpolados (o `install` é a única string passada à shell). Os ids são validados com
  `/^[a-z0-9][a-z0-9-]*$/`. Para a corrida e cada área: `git branch` + `git worktree add`. Num
  conflito, faz `git merge --abort` e segue para a área seguinte. O merge usa `--no-ff -m
  "merge crew/<runId>/<area>"`.
