# Plano 4 — Dialogs, componentes, temas, layouts, páginas e CRUD `notes`

> Executado inline (ver o plano 2). O plano fixa ficheiros, interfaces, comportamento e testes; o código vive nos commits.

**Goal:** Pôr a interface do núcleo a funcionar:
- layout da app com sidebar;
- confirmações e toasts globais;
- temas;
- páginas de conta e de administração;
- um recurso de exemplo completo (`notes`), que a skill `web-crud-resource` usa como molde.

**Spec:** §8, §9, §10, §11 e §4 (recurso de exemplo).

## Decisões

- **Forms:** um composable próprio `useZodForm(schema, initial)` com os schemas de `#shared/schemas`, em vez do vee-validate:
  - valida no cliente;
  - mapeia os `issues` de `validation.invalid` vindos do servidor para os campos;
  - trata do estado pending e do erro geral.

  É menos uma dependência, e o schema é o mesmo nos dois lados. Desvio consciente ao spec (§3).
- **shadcn via CLI:** dialog, alert-dialog, sheet, dropdown-menu, sidebar, table, badge, select, separator, tooltip, avatar, skeleton, tabs, sonner, textarea, switch.
- **`DataTable` próprio,** sem TanStack: colunas declarativas, pesquisa com `normalizeText`, ordenação e paginação.
  - Modo cliente por defeito.
  - Modo servidor quando recebe `total` e emite `update:query`.
- **Temas:** `app/assets/css/themes/<nome>.css` com o seletor `[data-theme="<nome>"]`.
  - O cookie `app-theme` é aplicado no SSR com `useHead({ htmlAttrs: { "data-theme": … } })`.
  - Precedência: preferência do utilizador (se `appearance.userThemes`), depois a default do admin, depois `default`.
  - Favicon SVG tingido com a cor primária do tema.
- **Navegação como dados** (`app/utils/navigation.ts`), filtrada por `can()`.

## Recurso `notes` (molde para a skill)

- **Base de dados:** `notes(id, title varchar(200), body text, author_id FK→users set null, created_at, updated_at)` e a migração `0002_notes`.
- **Validação:** `shared/schemas/notes.ts` com `noteCreateSchema` e `noteUpdateSchema`.
- **Service** `server/services/notes.ts`: `listNotes`, `getNote`, `createNote`, `updateNote`, `deleteNote`. Cada operação audita e publica `notes.*` em `res:notes` e `res:notes:<id>`.
- **API:** `server/api/notes/{index.get,index.post,[id].get,[id].patch,[id].delete}.ts`, com `assertPermission` da matriz (`notes`).
- **Página:** `/app/notes` com lista (`DataTable` + `useLiveResource`), criação e edição num `ResponsiveDialog`, e apagar com `useConfirm`.
- **Testes de API** (`test/api/notes.test.ts`):
  - o editor faz o CRUD;
  - o user só lê (403 nas escritas);
  - validação;
  - 404;
  - um socket subscrito em `res:notes` recebe `notes.created`, `notes.updated` e `notes.deleted`.

## Páginas

| Rota | Layout | Conteúdo |
|---|---|---|
| `/app` | app | saudação, StatCards (notas, utilizadores se tiver permissão) |
| `/app/notes` | app | CRUD de exemplo |
| `/conta` | app | perfil (nome), preferências (idioma, tema), sessões ativas (revogar) e link para a password |
| `/conta/password` | auth quando obrigatória, app caso contrário | já existe; passa a escolher o layout dinamicamente |
| `/admin/utilizadores` | app | tabela, criar (password mostrada uma vez), editar roles e ativo, reset, apagar (escrever o email para confirmar), convites, "ver como" |
| `/admin/definicoes` | app | separadores: segurança, aparência, idioma, manutenção |
| `/admin/auditoria` | app | tabela paginada no servidor, filtro por ação |
| `/privacidade` | public | texto base |
| `error.vue` | — | 403, 404 e 500 traduzidos |
